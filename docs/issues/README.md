# docs/issues

One Markdown file per known bug, TODO, or open question. Each file follows the same loose shape:

- **Status** — open / investigating / mitigated / closed
- **Symptoms** — what the user observes
- **Root cause** — what's actually happening, with file:line refs when applicable
- **Ideas / options** — possible fixes, ordered by ease or recommendation
- **Diagnostic steps** — exact commands or repro recipes
- **Decision log** — what we've already tried, what was ruled out, and why
